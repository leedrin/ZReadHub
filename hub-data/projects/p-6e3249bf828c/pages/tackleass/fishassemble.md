物品系统 - 钓具组装功能需求文档 (Alpha0)

版本: Alpha0

文档整理: Claude (基于李一同原始文档)

适用对象: Unity客户端开发、服务器开发、UI设计师

1. 系统概述

本模块允许玩家将不同的渔具配件（线、轮、钩、饵等）组装到鱼竿上，并支持方案保存、分享及一键购买缺失物品。

1.1 功能入口

背包/仓库: 鱼竿图标 -> 左键单击/右键详情 -> 点击“组装”。

局外主界面: 点击“组装”按钮直达。

2. 核心数据结构与配置 (Server & Shared)

本节梳理服务器需存储的数据及客户端需读取的静态配置。

2.1 静态配置表 (Config)

配置表名

关键字段

说明

ItemConfig (物品表)

ID, Brand, Name, Type, Attributes (强度/拉力等), ModelPath

基础物品信息

RodConfig (鱼竿配置)

ID, SlotList (默认槽位), AllowedRigs (允许的钓组ID列表), BaitWeightRange (饵重范围)

定义鱼竿的基础结构

RigConfig (钓组配置)

ID, Name, Tags, RequiredSlots (包含的槽位类型), PhysicsModel (物理结构参数)

定义不同的钓组（如德州钓组、铅头钩等）及其所需的配件槽位

2.2 玩家动态数据 (UserData)

当前组装状态: 记录每根鱼竿当前各个Slot（槽位）安装的 ItemUniqueID。

方案数据 (Schemes):

自定义方案列表（上限6个）。

包含：方案名、分享码、包含的物品ID列表。

物品状态:

耐久度 (Durability): 本体及部件的损耗百分比。

收藏状态 (IsFavorite): Bool值。

3. 功能模块详解 (Client Logic)

3.1 组装首页 (Main Assembly)

UI布局:

顶部: 页签切换（装配 / 方案）。

左侧/主要区域: Slot（槽位）区。

右侧: 属性窗口、交互按钮。

背景: 3D模型展示区。

A. Slot区逻辑 (核心)

动态生成: 根据当前鱼竿的配置 + 当前选择的“钓组(Rig)”动态显示槽位。

逻辑: RodConfig.BaseSlots + CurrentRig.ExtraSlots。

槽位状态:

未开放: 前置物品未安装（如未装主线，无法装子线）。

必须组装: 必填项，为空时高亮/置灰对应属性。

可组装: 选填项。

已组装: 显示图标。

异常状态: 损耗 < 30% (红色) / 已损坏 (损坏图标)。

缺失状态: 方案应用时，若背包/仓库均无此物品，显示特殊样式。

B. 属性窗口 (Attribute Window)

基础信息: 品牌 + 商品名 + 型号。

负载信息 (Load Info): 5项进度条 (竿身、渔轮、鱼线、子线、鱼钩)。

显示逻辑: 关联槽位有物品时显示，否则隐藏或置灰。

数值计算:

属性值 (灰色): 物品配置的原始值。

实际值 (黑色): 经损耗计算后的当前值 (ConfigValue * DurabilityFactor)。

变化值 (绿色/红): 预览替换物品时的差值。

UI警告: 实际值最低的一项需特殊标记（木桶效应）。

钓组信息:

显示当前钓组名称、Tag、介绍。

总重量检测: 若 (所有配件重量之和) > Rod.MaxBaitWeight 或 < Rod.Min，显示警告。

物理调整滑条: 若钓组支持（如调整铅坠位置），显示滑条控制物理参数（需同步3D模型）。

D. 3D模型展示

操作: 左键拖动旋转（横向/纵向轨道），滚轮缩放。

显隐规则:

未安装的部件不显示。

依赖关系的部件（如子线依赖主线）若前置未装，则不显示。

3.2 钓组切换 (Rig Switching)

入口：组装首页 -> 点击钓组修改按钮

列表展示: 显示该鱼竿支持的所有钓组。

状态: 使用中 / 已解锁 / 未解锁。

切换逻辑:

更改 CurrentRigID。

Slot重构:

移除旧钓组特有的Slot（如移除“德州钓组”的曲柄钩）。

新增新钓组的Slot（如“铅头钩”）。

记忆功能 (Priority 3): 切换回旧钓组时，尝试自动填入上次使用的物品（若背包中有）。

3.3 物品替换页 (Item Replacement)

入口：点击任意Slot

A. 物品筛选与排序

列表内容:

正在使用: 置顶。

近期装配: 最近使用的2个。

最常装配: 频次最高的3个。

已拥有:

排序: 收藏 > 未收藏 > 属性高低 > 名称。

不可用项: 参数不匹配（如尺寸不对）、类别未解锁 -> 放在最后，置灰。

B. 选中交互

选中: 更新右侧属性预览（显示负载变化条）。

按钮状态变化:

选中“正在使用” -> 显示 [卸下]。

选中“未使用”且匹配 -> 显示 [安装]。

选中“不匹配” -> 显示 [安装(置灰)] (点击提示不合适)。

选中“推荐/未拥有” -> 显示 [加入购物车] (Alpha0暂不做推荐，但需预留逻辑)。

3.4 方案系统 (Scheme System)

入口：顶部页签 -> 方案

A. 方案管理

自定义方案: 上限6个。支持保存、删除、分享（生成分享码）。

推荐方案: 配置表读取。

B. 保存与应用

保存: 将当前组装状态保存为方案。支持重命名。

应用 (Load):

若背包有所有物品 -> 直接组装。

一键加购: 若方案包含未拥有物品：

关卡内 -> 加入关卡内商店购物车。

关卡外 -> 加入外部商店购物车。

C. 搜索

输入分享码 -> 搜索并在推荐区显示新方案。

4. 开发优先级与暂缓项

4.1 核心开发 (Priority 1 - Alpha0必须完成)

基础组装流程（槽位显示、物品安装/卸下）。

属性面板的数值计算与负载条显示。

3D模型随组装动态变化。

钓组切换导致槽位变化的基础逻辑。

手持功能。

4.2 暂缓或低优先级 (Priority 3)

Slot记忆功能: 切换钓组时记录上次用的配件。

复杂的排序规则: "近期装配"、"最常装配"的统计逻辑（初期可仅按ID或获得时间排序）。

查看钓友方案: 社交相关功能。

5. 技术实现建议 (Unity)

5.1 客户端 (Client)

设计模式: 建议使用观察者模式 (Observer Pattern)。当 CurrentAssembly 数据发生变化时，广播事件：

UI_SlotController 监听并刷新图标。

UI_AttributeController 监听并重算负载条。

3D_ModelController 监听并实例化/销毁对应配件模型。

模型管理: 考虑到配件可能很多，建议使用对象池 (Object Pooling) 或按需异步加载 (Addressables)，避免切换物品时卡顿。

5.2 异常处理

物品丢失: 如果应用方案时，记录的 ItemID 在背包找不到（被卖了），需回退到“未安装”状态或寻找同类替代品（Alpha0建议直接留空）。

互斥逻辑: 需处理“排他性”安装，例如安装了特定的鱼饵，可能互斥掉某些类型的钩子（由配置表定义互斥组）。
