# 产品需求文档：UIProcess 可视化编辑器与数据驱动机制

## 1. 引言

本文档旨在阐述为现有 `UIProcess` 系统开发一套可视化编辑器和数据驱动播放机制的产品需求。该系统将允许美术、策划和开发者以图形化界面编排复杂的 UI 动画和交互流程，并能在运行时通过数据驱动进行加载和播放，从而提高开发效率、降低维护成本，并增强 UI 表现的灵活性。

## 2. 背景

当前项目中，`UIProcess` 系统已广泛应用于 UI 动画和流程控制。它通过 `UIProcessFactory` 以编程方式构建，并在 Tofu 组件中进行管理和播放。尽管 `UIProcess` 提供了强大的抽象和组合能力（串行/并行执行、自定义逻辑、延迟等），但其纯代码的实现方式限制了美术和策划直接参与 UI 流程的创作，且复杂流程的调整和预览成本较高。

本需求旨在借鉴 Unity 的 Timeline 和 Unreal Engine 的 Montage 编辑器等成熟经验，为 `UIProcess` 引入可视化编辑和数据驱动能力。

## 3. 目标

-   **提高开发效率：** 允许美术和策划通过可视化界面直观地编排 UI 动画和逻辑，减少对开发人员的依赖。
-   **降低迭代成本：** 快速调整和预览 UI 流程，缩短迭代周期。
-   **增强灵活性：** 支持运行时数据驱动加载和播放 `UIProcess`，便于热更新和动态内容配置。
-   **优化工作流：** 建立一个清晰的 UI 表现层与业务逻辑层分离的工作流。

## 4. 核心需求

### 4.1. 核心数据结构设计

为了实现可视化编辑和数据驱动，需要设计一套可序列化的数据结构来表示 `UIProcess` 及其所有配置。

-   **可序列化的 `UIProcess` 定义：**
    -   为每种 `UIProcess` 类型（例如 `CommonUIStateEffectProcess`、`ExecutorProcess`、延迟 Process 等）定义一个可序列化的元数据结构。
    -   该结构应包含：
        -   **类型标识符：** 用于在运行时反序列化时识别 `UIProcess` 类型。
        -   **可配置参数：** `UIProcess` 自身或其内部封装的逻辑所需的参数（例如，动画名称、状态名称、持续时间、回调函数名等）。
        -   **子 `UIProcess` 列表：** 用于表示组合 `UIProcess` 的子项。
        -   **执行模式：** 明确标识子 `UIProcess` 的执行关系（串行 `Serial` 或并行 `Parallel`）。
-   **Track（轨道）概念：**
    -   引入“轨道”作为组织 UI 行为的容器。每个轨道可以承载特定类型或功能的 `UIProcess` 片段。
    -   示例轨道类型：
        -   **动画轨道：** 用于控制 UI 元素的动画播放（例如，`AdvancedUIStateController` 状态）。
        -   **逻辑事件轨道：** 用于触发自定义 C# 方法或脚本。
        -   **音效轨道：** 用于播放音效。
        -   **延迟轨道：** 用于插入等待时间。
-   **Clip（片段）概念：**
    -   每个 Clip 代表时间轴上的一个 `UIProcess` 实例的引用或其配置数据。
    -   Clip 应包含：
        -   **开始时间 (StartTime)：** Clip 在时间轴上的起始点。
        -   **持续时间 (Duration)：** Clip 的播放时长。
        -   **关联 `UIProcess` 类型：** 指向具体的 `UIProcess` 定义。
        -   **参数配置：** `UIProcess` 实例所需的具体参数值。
-   **事件/回调点：**
    -   允许在时间轴的特定时间点定义可触发的自定义事件，这些事件可以在运行时被捕获并执行预定义的逻辑。

### 4.2. 编辑器功能

开发一个基于 Unity Editor 的可视化工具，提供以下核心功能：

-   **时间轴视图 (Timeline View)：**
    -   **可视化轨道管理：** 提供直观的界面来添加、删除、重排不同类型的轨道。
    -   **Clip 的可视化表示与编辑：** `UIProcess` 片段以可拖拽、可调整大小的图形化方块在时间轴上显示，直观展示其类型、名称和持续时间。支持 Clip 的复制、粘贴、删除。
    -   **时间轴导航与控制：** 具备播放头、缩放、平移、帧精确编辑等功能，方便用户精确定位和调整 UI 流程。提供播放、暂停、快进、倒退等播放控制。
    -   **关键帧/参数曲线编辑：** 对于支持动画参数的 `UIProcess`，提供关键帧编辑或参数曲线调整功能，实现更精细的动画控制。
-   **属性面板 (Inspector/Property Panel)：**
    -   当选中一个轨道或 Clip 时，在 Unity Inspector 面板中显示其详细属性和参数，并提供友好的 UI 控件进行编辑。
    -   能够根据选中的 `UIProcess` 类型动态加载相应的参数编辑器 UI。
-   **资源浏览器集成 (Asset Browser Integration)：**
    -   允许用户从 Unity Project 窗口中直接拖拽 UI 动画（例如 Animator Controller States）、音效文件、自定义脚本（封装为 `UIProcess` 类型）等到时间轴上，自动生成对应的 `UIProcess` 片段并配置参数。
-   **预览功能 (Preview Functionality)：**
    -   在 Unity Editor 中提供播放按钮，允许用户实时播放和预览时间轴所编排的 UI 效果，包括动画、逻辑和音效。
    -   支持暂停、快进、倒退等播放控制，并能同步显示 UI 状态变化。
-   **事件/通知系统：**
    -   允许用户在时间轴上添加自定义事件标记，并在预览或运行时触发相应的回调或消息，方便与其他系统集成。
-   **保存/加载 (Save/Load)：**
    -   提供将整个时间轴数据保存为 Unity ScriptableObject 或其他可序列化资产文件（例如 JSON, XML）的功能。
    -   能够从文件中加载时间轴数据，并在编辑器中恢复编辑状态。

### 4.3. 运行时支持

开发一套高效的运行时系统，能够加载和播放编辑器创建的 `UIProcess` 时间轴数据。

-   **数据解析器/加载器 (Data Parser/Loader)：**
    -   一个高效的运行时组件，能够解析编辑器生成的可序列化数据文件。
    -   根据数据中的 `UIProcess` 类型标识符和参数，动态地使用 `UIProcessFactory` 或通过注册表机制创建对应的 `UIProcess` 实例。
-   **运行时播放器 (Runtime Player)：**
    -   一个轻量级的运行时组件，负责根据加载的数据驱动 `UIProcess` 时间轴的播放。
    -   管理所有 `UIProcess` 的生命周期，处理串行/并行执行逻辑，精确控制延迟、回调和中断。
    -   需要与现有的 `UIProcessManager` 紧密集成，可以作为 `UIProcessManager` 的一个高级播放模式。
-   **事件触发器 (Event Triggering)：**
    -   运行时播放器在达到时间轴上定义的事件点时，能够触发注册的事件或回调。
-   **性能优化：**
    -   确保运行时加载和播放的效率，避免性能瓶颈，特别是对于移动平台。

## 5. 功能列表

除了基本的 `UIProcess` 编排（如 `AdvancedUIStateController` 状态切换）外，可视化工具需要支持以下功能：

-   **延迟等待 (Delay/Wait)：**
    -   **编辑器：** 提供“延迟”Clip 类型，用户可在时间轴上直接创建并设置持续时间。
    -   **运行时：** `UIProcessFactory` 扩展 `CreateDelayProcess(float delayTime)` 方法，内部使用协程或定时器实现精确延迟。
-   **输入打断 (Input Interruption)：**
    -   **编辑器：**
        -   为 Clip 或整个时间轴设置“可打断”标志。
        -   定义打断后的行为：立即停止、跳转到时间轴的特定片段、播放特定的打断动画。
        -   在时间轴上可视化标记可打断区域。
    -   **运行时：**
        -   `UIProcessManager` 提供 API 来接收外部打断信号（例如用户点击跳过动画），并根据编辑器的配置执行相应逻辑（例如，调用 `UIProcessStopAll()` 或跳转到指定 Clip）。
-   **循环 (Looping)：**
    -   **编辑器：**
        -   **自定义动画序列：** 允许用户选择时间轴上的任意一段 `UIProcess` Clip 序列，将其定义为一个可重用的“自定义动画序列”。
        -   **指定序列区间内循环：** 允许用户为这个“自定义动画序列”设置循环次数或无限循环。在时间轴上，可以直观地显示循环的起始和结束点。
        -   **跳转功能：** 提供“跳转”Clip 类型，允许用户在 `UIProcess` 播放过程中，跳转到时间轴上的其他指定位置或另一个自定义动画序列。
        -   **方便预览：** 在编辑器预览功能中，能够准确地模拟和展示循环和跳转的效果。
    -   **运行时：**
        -   `UIProcess` 系统需要支持根据数据定义，在运行时识别和执行指定序列的循环和跳转逻辑。
        -   `UIProcessFactory` 可以扩展 `CreateLoopProcess(string sequenceName, int loopCount)` 或 `CreateJumpProcess(string targetSequenceName)` 等方法。
-   **条件分支 (Conditional Branching)：**
    -   **编辑器：** 引入条件节点或分支轨道，允许用户根据运行时条件（例如，玩家等级、特定任务完成状态）选择不同的 `UIProcess` 播放路径。
    -   **运行时：** `UIProcess` 能够评估条件，并根据结果动态选择要播放的子 `UIProcess` 序列。
-   **参数化 (Parameterization)：**
    -   **编辑器：** 允许 `UIProcess` 片段接收外部参数，这些参数可以在编辑器中被暴露为可编辑的变量，甚至可以链接到其他数据源或动画曲线。
    -   **运行时：** 运行时播放器能够将外部参数注入到 `UIProcess` 实例中。
-   **与现有 `UIProcess` 系统的集成：**
    -   **`UIProcessFactory` 的扩展：** `UIProcessFactory` 需要扩展，以便能够根据数据文件中的描述创建 `UIProcess` 实例，而不仅仅是硬编码创建。
    -   **`IUITaskCompUIProcessManager` 的作用：** `UIProcessManager` 仍然是核心的播放器，负责调度和管理所有 `UIProcess` 的执行。可视化工具生成的 `UIProcess` 结构最终会传递给它进行管理。
    -   **`UIAdvancePlayingEffectInfo` 和 `AdvancedUIStateController` 的抽象：** 在可视化编辑器中，`AdvancedUIStateController` 的状态名称可以作为动画 Clip 的参数进行选择和配置。

## 6. 复杂组合案例分析

以 [`GameProject/Scripts/Runtime/UI/StickerPackageUnpack/StickerPackageUnpackUIController.cs:87`](GameProject/Scripts/Runtime/UI/StickerPackageUnpack/StickerPackageUnpackUIController.cs:87) 中 `StickerPackageUnpackEffectProcessCreate` 所示的撕卡包动画为例，如果使用可视化工具进行编排：

1.  **轨道设置：**
    *   **主动画轨道：** 放置“撕卡包动画”Clip。
    *   **卡牌抽取轨道 (多个)：** 根据需要，可以有多个轨道，每个轨道对应一张卡牌的抽取动画，可并行或串行。
    *   **卡牌展示轨道：** 放置每张卡牌的展示和消失 Clip。
    *   **逻辑事件轨道：** 用于在特定时间点触发自定义逻辑（例如，更新卡牌数据、播放音效、触发震动）。
    *   **音效轨道：** 用于播放背景音乐或特定音效。

2.  **Clip 编排：**
    *   **“撕卡包动画”Clip：** 放置在主动画轨道的起始位置，持续一段时间。
    *   **“抽卡动画”Clip：** 紧随“撕卡包动画”之后，可以根据卡牌数量，在并行轨道上放置多个，实现同时抽取多张卡牌的效果；或者在串行轨道上依次播放，实现逐张抽取的效果。
    *   **“卡牌展示”Clip：** 在每张卡牌抽取动画结束后触发。该 Clip 内部可能包含：
        *   一个短的“延迟”Clip，等待动画过渡。
        *   一个“显示卡牌详情”Clip，播放卡牌详情面板的显示动画。
        *   一个“隐藏卡牌详情”Clip，播放卡牌详情面板的隐藏动画。
    *   **逻辑事件 Clip：**
        *   在每张卡牌展示前，放置一个逻辑事件 Clip，用于更新 UI 上的卡牌数据。
        *   在所有卡牌动画结束后，放置一个逻辑事件 Clip，触发结算流程或跳转到下一个 UI。
    *   **音效 Clip：** 在时间轴的适当位置放置音效 Clip，同步动画播放音效。

3.  **参数配置：**
    *   动画 Clip 可以配置动画名称、播放速度、循环模式等。
    *   逻辑 Clip 可以通过下拉菜单选择预定义的 C# 方法或脚本资产，并配置其输入参数（例如，卡牌 ID）。
    *   延迟 Clip 可以直接在编辑器中设置延迟时间。

通过这样的可视化工具，美术和策划人员可以在不编写代码的情况下，通过直观的拖拽和参数配置，精确地编排和调整复杂的 UI 动画流程，大大提高开发效率和迭代速度。同时，数据驱动的机制允许在运行时加载和播放这些预设好的 UI 流程，实现了 UI 表现与核心业务逻辑的进一步解耦。

## 7. 验收标准

-   **功能完整性：** 所有核心需求和功能列表中的功能均能正常工作。
-   **易用性：** 编辑器界面直观，操作流畅，符合美术和策划的工作习惯。
-   **性能：** 编辑器和运行时播放器均能保持良好的性能，不影响游戏帧率。
-   **稳定性：** 系统在长时间使用和复杂场景下无崩溃、无明显 Bug。
-   **扩展性：** 易于添加新的 `UIProcess` 类型和新的编辑器功能。
-   **文档：** 提供清晰的开发和使用文档。

## 8. 未来展望

-   **更丰富的 `UIProcess` 类型：** 扩展更多内置的 `UIProcess` 类型，例如粒子特效播放、屏幕震动、相机动画等。
-   **集成外部工具：** 与 Unity 的 Animator、Particle System 等现有工具更深度地集成。
-   **版本控制：** 支持 `UIProcess` 时间轴资产的版本控制和合并。
-   **多人协作：** 支持团队成员同时编辑不同的 `UIProcess` 时间轴。
